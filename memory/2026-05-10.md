## TikTok Connector v2 Upgrade (4:45 PM)

Now that Jason has TikTok developer portal access, rebuilt the connector to use the current v2 API:

### OAuth v2 (replaced legacy v1 endpoints)
- Authorize: `https://www.tiktok.com/v2/auth/authorize/`
- Token: `POST https://open.tiktokapis.com/v2/oauth/token/`
- Revoke: `POST https://open.tiktokapis.com/v2/oauth/revoke/`
- Returns: access_token (24h), refresh_token (365d), open_id, scope

### Content Posting API v2 (replaced old `/share/video/upload/`)
- `POST /v2/post/publish/creator_info/query/` — required before posting, returns privacy options
- `POST /v2/post/publish/video/init/` — Direct Post video (FILE_UPLOAD or PULL_FROM_URL)
- `POST /v2/post/publish/content/init/` — Direct Post photo (up to 35 images)
- `POST /v2/post/publish/status/fetch/` — poll for PROCESSING_UPLOAD → PUBLISH_COMPLETE
- `PUT <upload_url>` — chunked video upload with Content-Range header

### Key changes
- PKCE now optional for web (required for mobile/desktop)
- `exchangeTikTokCode` now takes `{ codeVerifier?, redirectUri? }` instead of raw `state` string
- `getTikTokOAuthUrl` now takes `{ state, scopes?, codeChallenge? }` object
- `publishToTikTok` now queries creator_info first (per UX guidelines), validates privacy_level
- Added `initVideoPublish`, `uploadVideoChunk`, `initPhotoPublish`, `queryCreatorInfo`, `getPostStatus`, `revokeTikTokToken`
- No text-only posts supported (TikTok Content Posting API requires video or photo)
- No analytics via Content Posting API (need Research API or public page scrape)

### Rate limits (per access_token)
- Creator info: 20 req/min
- Video init: 6 req/min
- Status fetch: 30 req/min

### Files changed
- `packages/api/src/connectors/tiktok.ts` — full rewrite (v2 API)
- `packages/api/src/connectors/index.ts` — updated exports
- `packages/api/src/routes/channels.ts` — updated auth URL calls
- `packages/api/src/routes/callbacks.ts` — updated token exchange call
- `memory/connector-spec.md` — updated TikTok section with v2 details

### ⚠️ Known limitations
- Unaudited clients can only post to private accounts — content will be SELF_ONLY
- To enable public posting, app must undergo audit at https://developers.tiktok.com/application/content-posting-api
- Photo URLs must be from verified domains (verify in dev portal)
