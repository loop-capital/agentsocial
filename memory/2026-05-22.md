## Voice Receptionist Architecture — DESIGNED + CODED

Jason asked how to handle the voice receptionist properly.

**Architecture Decision: 3-Layer System**
- Layer 1: Dograh (transport — STT/TTS/phone)
- Layer 2: LLM with dynamic system prompt (intelligence)
- Layer 3: Business profile config (knowledge — structured data injected into prompt)

**Key Decisions:**
- NO Graphify per business — overkill for ~20 data points (services, hours, FAQs)
- NO RAG — prompt injection handles salon-level knowledge perfectly
- The agent CAN respond outside workflows because ALL business knowledge is in the system prompt
- Dynamic prompt builder injects real-time context (current time, open/closed status, special notes)
- Function calling enables live booking, availability checks, transfers, SMS
- Post-call webhooks feed data back to AgentSocial CRM

**Files Created:**
- `packages/voice-agent/docs/architecture.md` — Full architecture doc
