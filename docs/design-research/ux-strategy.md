## 2. GSAP Scroll Animation Best Practices

### Core Principles for Landing Pages
- **ScrollTrigger** — Link any GSAP animation to scroll position
- **Pin sections** — Hold sections in place while inner content animates
- **Scrubbed timelines** — Animation progress tied to scroll position
- **Clamp values** — Use `clamp()` to prevent above-fold partial animations
- **Batch triggers** — Group animations for performance
- **Start/end positions** — "top bottom" (default) for entering viewport; "top top" for pinned sections

### Landing Page Animation Patterns
1. **Hero sequence:** Preloader → headline reveal → subtitle fade → CTA entrance
2. **Section reveals:** Fade + translateY (30-50px) on scroll enter
3. **Number counters:** Animate from 0 to final value on scroll
4. **Horizontal scroll:** Pin section, scroll through features horizontally
5. **Staggered lists:** Items enter one by one with 0.1s delay
6. **Morph transitions:** Elements transform between states as you scroll
7. **Parallax layers:** Background moves slower than foreground

### Performance Guidelines
- Use `will-change` sparingly (only on animating elements)
- Prefer `transform` and `opacity` (GPU-composited)
- Avoid animating `width`, `height`, `margin` (trigger layout)
- Use `invalidateOnRefresh: true` for responsive recalculation
- Batch ScrollTrigger instances with `ScrollTrigger.batch()`
- Consider `matchMedia()` for different mobile/ desktop animations

### Basys Implementation Plan
- Hero: Staggered text reveal + gradient mesh animation
- How It Works: Step-by-step scrub (scroll controls step progression)
- Features: Bento grid items stagger in
- Social Proof: Testimonial carousel with smooth scroll
- Pricing: Number counter animation ($0 → $199)
- CTA sections: Fade + scale entrance

## 3. Glassmorphism + Gradient Mesh 2026

### "Dark Glassmorphism" — Defining 2026 UI Aesthetic

**Core concept:** Frosted glass panels over vibrant gradient orbs
- Background: Dark (#0A0A0A to #111111)
- Gradient orbs: Deep purples, neon blues, hot pinks floating behind UI
- Glass panels: `backdrop-filter: blur(16px)` + semi-transparent white
- Borders: 1px semi-transparent white (rgba(255,255,255,0.1))

**CSS Implementation:**
```css
.glass-card {
  background: rgba(255, 255, 255, 0.05);
  backdrop-filter: blur(16px);
  -webkit-backdrop-filter: blur(16px);
  border: 1px solid rgba(255, 255, 255, 0.1);
  border-radius: 16px;
}

.gradient-orb {
  position: absolute;
  width: 400px;
  height: 400px;
  border-radius: 50%;
  filter: blur(80px);
  opacity: 0.4;
  /* Animated position with GSAP */
}
```

**Accessibility considerations:**
- Text on glass must maintain WCAG AA contrast (4.5:1 minimum)
- Use darker glass backgrounds for better text contrast
- Test with blur disabled (some users have motion preferences)
- Provide fallback solid backgrounds
- Don't stack more than 2 glass layers

**Basys approach:**
- Hero section: Dark background with animated gradient orbs (teal + purple + green)
- Feature cards: Glass panels on dark sections
- Pricing cards: Glass with subtle green orb glow
- Navigation: Glassmorphic sticky nav

## 4. Bento Grid Layout for Health SaaS

### What Is Bento Grid?
- Inspired by Japanese bento box — compartmentalized grid
- Popularized by Apple's product summary slides
- Now dominant in SaaS landing pages (43+ documented examples on SaaSFrame)
- Grid-based layout with distinct sections of varying sizes

### Bento Grid Best Practices
- **Vary cell sizes** — Not all equal; 1-2 large hero cells + smaller feature cells
- **2-3 cell sizes** — Large (2x2), Medium (2x1 or 1x2), Small (1x1)
- **12-column base** — Allows flexible combinations
- **Visual hierarchy** — Most important feature gets the largest cell
- **Icons/illustrations** — Each cell has a visual element
- **Hover interactions** — Cards respond to hover with subtle scale/glow
- **Dark and light variants** — Both work; dark is trendier for SaaS

## 5. Dark/Light Alternating Sections

### Pattern Description
- Alternate between dark (#0A0A0A) and light (#FAFAFA) sections as user scrolls
- Creates visual rhythm and breaks monotony
- Editorial feel — like reading a well-designed magazine
- "A sleek, modern website that alternates between light and dark sections as you scroll — a trend that feels both editorial and trendy" (ReallyGoodDesigns)

### Implementation for Basys
```
Section 1: DARK  — Hero (glassmorphism, gradient orbs)
Section 2: LIGHT — Problem/Solution (warm, approachable)
Section 3: DARK  — How It Works (tech-forward, step process)
Section 4: LIGHT — Features Bento Grid (clean, readable)
Section 5: DARK  — Social Proof (dramatic, testimonial spotlight)
Section 6: LIGHT — Pricing (clear, comparison-friendly)
Section 7: DARK  — Final CTA (impactful, gradient)
```

### CSS Approach
- Use `.theme-dark` and `.theme-light` classes on sections
- Smooth color transitions between sections (CSS `transition: background-color 0.3s`)
- Or: Use gradient overlaps at section boundaries for seamless blending
- Tailwind: `dark:bg-gray-950` / `bg-white` on alternating sections
- Consider CSS `color-scheme` property for native dark mode support

### Accessibility Notes
- Ensure WCAG AA contrast in both modes
- Dark sections: White text (#FFFFFF) on dark bg (#0A0A0A) = 19.3:1 ✓
- Light sections: Dark text (#1A1A2E) on white bg (#FFFFFF) = 15.4:1 ✓
- Accent colors must work on both backgrounds (test teal on dark AND light)

## 6. Micro-Interactions 2026

### Categories of Micro-Interactions

**1. Hover States**
- Buttons: Scale(1.02) + subtle shadow increase + color shift
- Cards: TranslateY(-4px) + shadow depth increase + border glow
- Links: Underline animation (width expansion from left)
- Icons: Rotation or color shift on hover

**2. Click/Tap Feedback**
- Button press: Scale(0.98) + ripple effect
- Toggle: Smooth spring animation
- Form submission: Loading spinner → checkmark transition
- Download CTA: Button morphs to progress bar

**3. Scroll-Triggered Entrances**
- Fade + translateY(20px → 0)
- Stagger: 0.08s delay between sibling elements
- Scale: 0.95 → 1.0 for cards
- Clip-path reveal for hero elements

**4. State Transitions**
- Loading → Success: Skeleton → content with fade
- Empty → Populated: Smooth height + opacity
- Error → Correct: Shake animation + red → green
- Selected states: Border glow + subtle scale

**5. Data Visualizations**
- Number counters: Animate from 0 to final value
- Charts: Draw-in animation (line/path animation)
- Progress bars: Width animation with ease-out
- Sparklines: Sequential point plotting

## 7. Fluid Typography with CSS clamp()

### The Core Concept
`font-size: clamp(min, preferred, max);`
- **min:** Minimum font size (mobile baseline)
- **preferred:** Preferred size with viewport units (e.g., `2.5vw + 1rem`)
- **max:** Maximum font size (desktop cap)

### Basys Typography Scale with clamp()

```css
:root {
  /* Fluid Type Scale — Min 320px, Max 1440px */

  /* Display — Hero headlines */
  --font-display: clamp(2.5rem, 5vw + 1rem, 4.5rem);

  /* H1 — Section headlines */
  --font-h1: clamp(2rem, 4vw + 0.75rem, 3.5rem);

  /* H2 — Sub-sections */
  --font-h2: clamp(1.5rem, 3vw + 0.5rem, 2.5rem);

  /* H3 — Card titles */
  --font-h3: clamp(1.25rem, 2vw + 0.25rem, 1.75rem);

  /* Body — Primary text */
  --font-body: clamp(1rem, 1.2vw + 0.5rem, 1.125rem);

  /* Small — Labels, captions */
  --font-small: clamp(0.875rem, 1vw + 0.4rem, 1rem);

  /* Micro — Trust badges, disclaimers */
  --font-micro: clamp(0.75rem, 0.8vw + 0.4rem, 0.875rem);
}
```

### Utopia Fluid Type Scale (Recommended Tool)
- Use [utopia.fyi](https://utopia.fyi) to generate clamp values
- Set min viewport: 320px, max viewport: 1440px
- Define modular scale (e.g., 1.25 Major Third)
- Export CSS custom properties

### Responsive Considerations
- No media queries needed for typography
- Headlines scale smoothly from mobile to desktop
- Line heights adjust with `clamp()` too: `line-height: clamp(1.2, 1.3, 1.4)`
- Letter tracking tightens at larger sizes: `letter-spacing: clamp(-0.02em, -0.03vw, 0)`

### Option 1: Benefit-First (Recommended)
**"Your health, decoded by AI"**
- Short, memorable, benefit-focused

- "AI" establishes tech credibility
- Works for both health-savvy and general audiences

**"The supplement plan your body actually needs"**
- Direct, personal, outcome-specific
- Differentiates from generic health platforms
- Speaks to the supplement market specifically
- Risk: Too narrow for broader health positioning

**"The operating system for your health"**
- Category-creating language (like Linear)
- "Operating system" implies comprehensive control
- Tech-savvy audience will love this
- Risk: May feel too abstract for some users

**"1,000 biomarkers. One personalized plan. Real doctors behind the AI."**
- Trust cascade in headline form
- Specific numbers build credibility
- "Real doctors" addresses AI skepticism
- Risk: Long, may not work on mobile

### Option 5: Aspirational
**"Get better at being healthy, every year"**
- (Similar to Superpower — proven effective)
- Aspirational, progressive, optimistic
- "Every year" implies longevity
- Risk: Less differentiated
